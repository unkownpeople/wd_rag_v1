# V1 表格上下文契约修改记录

## 修改目标

修复完整表格已经存在于正式切块 JSONL，但运行时 `assemble_context()` 只能从 Qdrant payload 读取 `raw_matrix`，导致完整表格展开分支不可用的问题。

## 修改边界

本批次只修改：

- `embeddings/retrieve.py`
- `embeddings/test_retrieve.py`
- `scripts/audit_tcs_pdf_qdrant.py`

不修改解析、清洗、切块、Embedding 文本、向量、Qdrant 持久化数据、Planner、提示词、前端或评测题。

## 实现方式

`BM25Index` 本来就会读取当前 `chunk_dir` 的全部正式切块，因此在同一次加载中增加 `table_matrices` 注册表：

```text
table_group_id / table_id
    -> 一份完整 raw_matrix
```

当前数据检查为 648 个表格块、176 个表格组。切块中重复保存的矩阵字符量约为去重后 6.32 倍，因此运行时只保留每组一份，不把完整矩阵复制进每个 Qdrant payload。

Dense、BM25 和 Hybrid 召回获得表格块后，`QdrantRetriever` 根据 `table_group_id` 关联注册表，并把矩阵放入仅运行时存在的 `_table_matrix` 字段。`assemble_context()` 优先读取 `_table_matrix`，同时继续兼容旧的 `payload.raw_matrix`。

若同一个 `table_group_id` 在切块中出现不同完整矩阵，索引初始化直接失败，不静默选择其中一份。

## 预期结果

- Qdrant payload 继续只保存命中行、表头元数据和 `raw_matrix_sha256`。
- 完整表格仍以 UTF-8 切块 JSONL 为唯一原始副本。
- 命中任意表格行后，运行时可以恢复该组完整表格。
- 同一表格组在上下文中只展开一次。
- 不需要重新生成向量或重建数据库。
