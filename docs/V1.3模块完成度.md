# V1.3 模块完成度

核对日期：2026-09-11。代码基线：`3203975`；本次仅更新文档和配置模板预算。

## 结论与计分口径

参考 [企业知识库检索增强项目拆解](https://cjt.dycq.xyz/project-be-rag.html)，沿用此前 A/B/C 各 10 项的工程拆分。基本满足计 1，部分满足计 0.5，未满足计 0。该拆分是本项目的人工评估表，不是参考页面给出的评分标准；百分比不是准确率、生产就绪率或剩余工期。

多用户、租户、身份鉴权和文档权限始终不计入这 30 项。稳定外部 ID 同步、定期对账仍列在历史口径内，同时给出排除这两项后的当前执行范围。

| 模块 | 基本 / 部分 / 未满足 | 历史完整口径 | 当前执行范围 | 结论 |
| --- | --- | ---: | ---: | --- |
| 文档入库与分块治理 | 3 / 4 / 3 | 5/10 = 50% | 5/8 = 62.5% | 基础入库可用，更新一致性与质量治理未闭环 |
| 混合检索 | 6 / 4 / 0 | 8/10 = 80% | 8/10 = 80% | 当前最小检索链路已交付，广泛验证尚不足 |
| 答案溯源与拒答 | 2 / 8 / 0 | 6/10 = 60% | 6/10 = 60% | 引用、拒答和观察诊断可用，语义保障仍有限 |
| 合计 | 11 / 16 / 3 | 19/30 ≈ 63.3% | 19/28 ≈ 67.9% | 单用户最小流程已跑通 |

旧表中的 50% 和 80% 保留。55% 调整为 60%，仅来自 C10 从“未满足”改为“部分满足”：数值检查已支持观察模式并有实测抽查，但没有系统抽样和误判率统计。删除生成层自动裁剪、改写和复审，不等于计算与推理准确率提升，也不把这次简化重复计分。

“混合检索最小链路完成”指约定实现范围和小样本验收完成；“80%”还包含术语保护、收益评测和广泛数据验证，两者分母不同。

## 答案溯源与拒答

| 编号 | 能力 | 状态 | 依据与缺口 |
| --- | --- | --- | --- |
| C1 | 引用 ID 存在性 | 基本 | `validate_citations` 检查引用编号与必要来源元数据 |
| C2 | 数值日期归一化与事实回查 | 部分 | `validate_answer_facts` 保留诊断；自然表达、换算和跨句派生值仍有限制 |
| C3 | 校验与拒答过程记录 | 基本 | `generation`、`refusal`、`fact_check` 和 `rag_api/audit.py` 记录当前实际流程 |
| C4 | 逐论断引用相符性 | 部分 | 数值回查不证明公司、年份、指标、因果关系对应正确 |
| C5 | 入口拒答和分档阈值 | 部分 | 空证据、相关度门槛存在；没有经风险分档校准的误拒指标 |
| C6 | 类型前置和替代路径 | 部分 | 风险问题前置拦截，有换问/核查提示；无人工工单闭环 |
| C7 | 核心失败判定与输出降级 | 部分 | 无效引用会替换回答；尚不能可靠判定复合答案核心事实失败，数值诊断不作阻断 |
| C8 | 来源、版本、更新时间回显 | 部分 | 有文件、位置和 source_revision；缺可靠源更新时间及完整版本展示 |
| C9 | 拒答正确性和复合回归 | 部分 | 有构造回归和真实复合题；误拒、漏拒尚无系统人工评测 |
| C10 | 观察模式和误判抽查 | 部分 | `validation_mode=observe` 已接入，诊断异常也保留答案；缺固定抽样、人工标签和误判率统计 |

当前答案单次生成，通过引用检查后原样返回。观察模式解决检查器干预输出的问题，不负责保证模型推理正确。微软实测 CAGR 的 13.36%、21.33% 应为 13.35%、21.32%；另有超出召回证据范围的“整份年报未披露”判断风险。
