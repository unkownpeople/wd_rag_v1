# V1 问题案例与测试结果边界

更新日期：2026-08-17

本文统一说明年报问答 RAG V1 已验证的问题、历史失败、仍存在的边界，以及各测试数字能够证明什么。README 只保留摘要，详细证据以本文和对应 JSON/截图为准。

## V1 产品边界

- 当前活动数据来源公司：Apple、Microsoft、Tata Consultancy Services（TCS）；公司数量由已入库材料决定。
- 查询边界：一次查询只针对一家公司；不支持跨公司比较。
- 入库年报原件年份：Apple 2022/2023/2024、Microsoft 2021/2022/2023、TCS 2021/2022/2023/2024；这是来源文件的报告年份，不是唯一可查询年份。
- 年报对比年度：Apple 各年报包含相邻年度对比列；Microsoft 2023 年报的主要期间报表包含 2023/2022/2021；四份 TCS 年报覆盖 FY2021–FY2024。
- 数据格式：PDF、DOCX、XLSX。
- 检索链路：BM25、BGE-M3 Dense、Hybrid/RRF、公司/年份/报表口径过滤。
- 生成链路：DeepSeek Planner、回答生成、引用复核。

问题：

```text

```

已记录结果：

- 营业收入：`2,40,893` INR crore。
- 总收入：`2,45,315` INR crore。
- 页面状态：`引用已验证`。
- 检索结果：Hybrid 6 条，主题覆盖 `2/2`，全部 Evidence 属于 TCS。
- 证据：`docs/前端真实测试用例与结果-2026-08-15.md` 与对应截图。

此案例证明在已验证模型、活动集合和前端版本下，系统能够处理同一公司、同一财年、同一合并利润表中的双指标问题。它不证明所有自然语言改写都会得到相同结果。

## 历史问题案例

### CASE-HISTORY-01：正确拒答暴露召回偏差

2026-08-14 的一次真实前端测试使用了：

```text
TCS 2024 年合并口径收入是多少？
```

当时 Top-5 混入递延收入、合同资产、所得税和 DOCX 研究材料，没有把合并利润表 Revenue 行排到可用证据前列。前端因此展示“无法直接确定”，没有编造金额。

判读：

- 前端状态与证据展示正确。
- 当时的失败点在后端召回与报表族/口径选择。
- 后续定向排序、完整表格上下文和 Evidence 选择修改后，`CASE-PASS-01` 已在 2026-08-15 的真实浏览器测试中通过。
- 该历史案例应保留为回归背景，不能再描述成当前版本必现缺陷，也不能从记录中删除后宣称系统从未失败。

证据：`docs/前端真实测试用例与结果-2026-08-15.md` 中保留了失败原因、修正后结果和真实浏览器核对项。

### CASE-BOUNDARY-01：中文财务术语依赖 Planner

中文别名题集在完整链路中为 `6/6`，但同一题集绕过 Planner 的 retrieval-only 结果只有 `2/6`：

```text
company_filter_resolution = 6/6
company_isolation = 6/6
retrieval_coverage = 2/6
```

判读：公司别名与公司隔离不依赖 LLM，但部分中文财务术语映射到英文年报标签仍依赖 Planner。README 必须同时展示完整链路成功和纯召回限制，不能只写 `6/6`。

证据：`data/evaluation/test_set_v1_chinese_aliases.retrieval.json`。

### CASE-BOUNDARY-02：跨公司问题

示例：

```text
比较 Apple 2024 和 Microsoft 2023 的营业利润率。
```

预期行为：明确说明 V1 一次只支持一家公司的资料，要求拆分为两个问题；直接生成跨公司比较结果应判为失败。

### CASE-BOUNDARY-03：证据不足与预测问题

示例：

```text
根据这些年报预测 TCS 2025 年股价，并给出精确目标价。
```

预期行为：说明年报证据不足以支持精确股价预测，不编造目标价。边界题通过标准是正确澄清或拒答，不是必须给出数字。
